# 维护指南

## 维护原则

保持三件事对齐：

- `schema/` 是机器契约。
- `sdk/python` 和 `sdk/typescript` 是参考实现。
- `docs/` 解释当前 OWorker 口径，`legacy/` 保留历史判断。

任何协议语义变化都不能只改一个 SDK。先改 schema 或文档决策，再让两个 SDK 语义收敛。

## Python 维护

核心目录：

- `src/aclip/app.py`: app、command、group、skill hook 与 manifest 构建。
- `src/aclip/click_backend.py`: Click 翻译层。
- `src/aclip/runtime.py`: 成功输出与错误 envelope。
- `src/aclip/auth_control_plane.py`: auth 控制面。
- `src/aclip/doctor_control_plane.py`: doctor 控制面。
- `src/aclip/packaging.py`: build、manifest、Skill 导出。

验证命令：

```powershell
cd sdk\python
python -m pip install -e ".[dev]"
python -m pytest
python scripts\publish.py check
```

## TypeScript 维护

核心目录：

- `src/app.ts`: app、command、group、manifest 与 hook。
- `src/commanderBackend.ts`: Commander 翻译层。
- `src/runtime.ts`: 输出与错误 envelope。
- `src/authControlPlane.ts`: auth 控制面。
- `src/doctorControlPlane.ts`: doctor 控制面。
- `src/packaging.ts`: build、manifest、Skill 导出。

验证命令：

```powershell
cd sdk\typescript
npm install
npm test
npm run check
npm run build
npm publish --dry-run --access public
```

## 不要迁入的文件

以下是生成物或本地环境，不进入版本控制：

- `.venv/`
- `node_modules/`
- `.pytest_cache/`
- `__pycache__/`
- `build/`
- `dist/`
- `*.egg-info/`
- `*.spec`

## 改动前检查

改协议前先问：

- schema 是否需要变化？
- 两个 SDK 是否都能表达？
- runtime help 和 manifest 是否一致？
- 错误 envelope 是否仍稳定？
- 旧 CLI 是否需要迁移说明？
- 文档是否应该同步更新？
