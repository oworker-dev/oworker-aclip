# 项目范围与维护边界

## 当前维护范围

OWorker ACLIP 维护以下内容：

- `schema/`: ACLIP 机器可读协议契约。
- `sdk/python`: Python 参考 SDK、示例、测试和发布脚本。
- `sdk/typescript`: TypeScript 参考 SDK、示例、测试和发布脚本。
- `docs/public`: 中文优先的外部使用者文档。
- `docs/internal`: 维护者文档、发布流程和注册中心状态。

## 所属标准层级

OWorker ACLIP 属于：

```text
OWorker Open System
└─ Agent-Native Service Standard (ANSS)
   └─ ACLIP / oworker-aclip
```

OWorker Open System / Agent-Native Service 是由 OWorker 团队维护的开放标准与开源工具体系，不是 OWorker 平台私有技术。OWorker 是维护者、首个核心应用者和核心受益者之一。

ACLIP 在 ANSS 中负责 CLI 能力：命令树、参数、runtime help、manifest、auth、doctor、error envelope、packaging 和 Skill export。后续 Agent-Native Service Kit / Suite 可以复用这些能力来构建标准 Agent 原生服务。

## 公开入口

- GitHub: `https://github.com/oworker-dev/oworker-aclip`
- npm: `@oworker/aclip`
- PyPI: `oworker-aclip`

Python 的包名是 `oworker-aclip`，代码 import path 保持 `aclip`。这不是品牌残留，而是 SDK 命名空间和协议命名空间，避免用户代码被包名变化牵动。

## 兼容边界

维护时优先保证：

- `manifest`、runtime help、error envelope、auth、doctor、Skill hook 的协议语义稳定。
- Python SDK 与 TypeScript SDK 在协议输出上保持一致。
- registry README、public docs 和示例代码都能直接上手。
- 发布流程可以重复执行，并且失败状态可追溯。

不承诺：

- 维护历史短名 alias。
- 将 ACLIP core 扩展成 live session、REPL、浏览器控制或多 Agent 编排框架。
- 在 public 文档中暴露维护背景或历史迁移叙事。

## 维护者检查

每次修改协议、SDK 或文档前，先判断变更是否会影响：

- `schema/*.schema.json`
- `sdk/python/src/aclip/_schema/`
- `sdk/typescript/schema/`
- `docs/public/参考`
- `sdk/python/README.md`
- `sdk/typescript/README.md`

影响任一项时，必须同步对应 SDK、测试和文档。
