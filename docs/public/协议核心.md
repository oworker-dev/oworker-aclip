# 协议核心

## 三层结构

ACLIP 被拆成三层：

- 协议契约层：`schema/` 下的 JSON Schema 是机器可读事实源。
- 参考 SDK 层：`sdk/python` 和 `sdk/typescript` 把协议翻译到 Click 与 Commander。
- 构建与导出层：SDK 提供打包、sidecar manifest、Skill 导出和示例 CLI。

协议文档解释语义，schema 约束结构，SDK 证明协议能被真实 CLI 使用。

## 一个 ACLIP CLI 必须描述什么

核心对象是 `AclipApp`。一个 app 至少包含：

- CLI 名称、版本、摘要和描述。
- 命令或命令组。
- 参数定义、类型、默认值和说明。
- 示例命令。
- 可选的认证凭证声明。
- 可选的 doctor 诊断控制面。
- 可选的 Skill hook。
- 可选的 distribution 元数据。

这些信息会被用于运行时帮助、sidecar manifest、打包产物和 Agent 消费。

## 帮助与渐进披露

ACLIP 约束帮助输出的重点是渐进披露：

- 根帮助给出 CLI 摘要、命令索引和下一步。
- 命令组帮助只展开当前组。
- 叶子命令帮助给出参数、示例、认证要求和返回语义。
- `--help` 面向人类，`--aclip-help` 面向 Agent。

这样 Agent 不需要一次读取整套 CLI 文档，也不会因为普通帮助文本格式漂移而失去判断依据。

## 成功输出与错误输出

ACLIP 保留 CLI 作者对成功 stdout 的控制权。成功命令可以输出人类可读文本、JSON、表格或空输出。

错误必须尽量结构化。SDK 提供 error envelope，核心字段包括：

- `code`: 稳定错误码。
- `message`: 人类可读说明。
- `details`: 机器可读细节。
- `retryable`: 是否值得重试。
- `nextAction`: 建议 Agent 下一步动作。

认证相关错误使用标准错误码：`auth_required`、`invalid_credential`、`expired_credential`。

## Manifest 与分发

打包命令会在 CLI artifact 旁生成 `.aclip.json` sidecar manifest。manifest 用来告诉 Agent：

- artifact 对应哪个 CLI。
- 版本与协议版本。
- 命令树与参数。
- 凭证来源。
- 分发来源，例如 npm package 或 local binary。

manifest 必须通过 `schema/manifest.schema.json` 验证。

## 明确边界

ACLIP 不标准化长期 live session、浏览器控制、REPL、多 Agent 编排或服务排名。它只处理一次性 CLI 命令的可发现、可解释、可诊断和可分发问题。
