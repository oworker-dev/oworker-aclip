# 认证、诊断与错误

## Credential

ACLIP 标准化两类凭证来源：

- `env`: 环境变量，例如 `NOTES_TOKEN`。
- `file`: 本地文件路径，例如 `.secrets/notes-token.txt`。

manifest 和 runtime help 可以暴露凭证来源、是否必需和说明，但不能输出凭证值。

## Auth 控制面

`auth` 是可选命令组。推荐命令：

- `auth login`
- `auth status`
- `auth logout`

认证状态建议包含 principal、状态、过期时间、下一步动作等机器可读字段。

## 标准认证错误

- `auth_required`: 缺少必需凭证。
- `invalid_credential`: 凭证存在但不可用。
- `expired_credential`: 凭证过期。

Agent 应优先根据错误码和 next action 决定是否提示用户、刷新凭证或停止任务。

## Doctor 控制面

`doctor` 也是可选命令组。推荐命令：

- `doctor check`: 只检查。
- `doctor fix`: 尝试修复可修复项。

每个 check 建议包含稳定 name、status、message、remediation 和可选 details。状态应能区分 `ok`、`warning`、`error`、`skipped`。

## 错误 Envelope

错误 envelope 的目标不是替代 stderr，而是给 Agent 一个稳定判断层。人类仍然可以看到错误文本，Agent 则读取 code、retryable、details 和 nextAction。
