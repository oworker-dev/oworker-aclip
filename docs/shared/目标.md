# 项目目标

## 最终目标

发布 OWorker ACLIP。

形成可维护、可安装、可被外部开发者直接上手的 ACLIP 协议、SDK、文档包和开源发布入口，并把它稳定定位在 OWorker Open System -> Agent-Native Service Standard (ANSS) 下。

## 背景与理由

普通 CLI 对人类足够自然，但 Agent 需要稳定读取命令、参数、认证、诊断、错误和 Skill 导出信息。OWorker ACLIP 的目标是把这些约定沉淀为清晰协议和双语言 SDK，让开发者可以快速构建 Agent-friendly CLI，并为 Agent-Native Service Kit / Suite 提供底层 CLI 能力。

## 完成标准

- 新项目使用 APCC 管理项目概览、目标、计划和任务。
- 公开文档中文优先，外部使用者能快速安装并写出第一个 CLI。
- 内部文档说明维护边界、测试矩阵、发布流程和兼容策略。
- npm、PyPI、GitHub 入口迁移到 OWorker 身份。

## 明确不做什么

- 不把协议名 `aclip` 改成 OWorker 私有名。
- 不破坏 Python import path `aclip`。
- 不自动发布历史 PyPI 短名 alias `aclip`。
- 不把 live session、浏览器控制、REPL 或多 Agent 编排纳入 ACLIP core。

## 当前进度摘要

项目位于 `project/open-system/anss/oworker-aclip`，当前文档站点使用 APCC 运行。GitHub 和 npm 入口已建立，PyPI 入口仍等待限流解除后继续发布。
