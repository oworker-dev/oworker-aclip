# 项目目标

## 最终目标

发布 OWorker ACLIP。

将 Rendo 归档的 `aclip` 无损迁移到 OWorker 生态，形成可维护的协议、SDK、文档包和开源发布入口。

## 背景与理由

Rendo 归档版 `aclip` 已经完成协议、schema、双语言 SDK、认证、诊断、Skill 导出、打包和示例 CLI 的完整闭环。如果只保留压缩描述，随着归档目录被清理，协议判断、产品边界和实现方法会丢失。

OWorker 需要把这套能力迁移成可公开使用、可继续维护、可被 Agent 生态发现的基础设施。

## 完成标准

- `rendo-archived/aclip` 的源码、schema、测试和原始文档被完整迁移或归档。
- 新项目使用 APCC 管理项目概览、目标、计划和任务。
- 公开文档中文优先，外部使用者能快速安装并写出第一个 CLI。
- 内部文档说明维护边界、测试矩阵、发布流程和迁移兼容策略。
- npm、PyPI、GitHub 入口迁移到 OWorker 身份。

## 明确不做什么

- 不把协议名 `aclip` 改成 OWorker 私有名。
- 不破坏 Python import path `aclip`。
- 不自动发布历史 PyPI 短名 alias `aclip`。
- 不把 live session、浏览器控制、REPL 或多 Agent 编排纳入 ACLIP core。

## 当前进度摘要

迁移任务已进入执行阶段。新项目位于 `project/oworker-aclip`，当前文档站点使用 APCC 运行。
